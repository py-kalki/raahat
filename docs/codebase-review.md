# Raahat implementation review — 21 October 2026

## Architecture and execution flow

The pnpm workspace contains an Expo SDK 52 / React Native 0.76 mobile app,
an Express API with Socket.IO and Prisma/PostgreSQL, a shared package of Zod
schemas, events and design tokens, and a GPS simulator. The shared package's
entry point is compiled `dist/index.js`, so it must be built before mobile bundling.

The app enters through `apps/mobile/index.js` and Expo Router. `_layout.tsx`
configures navigation. Authentication is held in a Zustand store; the API client
adds its bearer token, while the socket manager uses the same API origin and a
JWT handshake. Driver screens create and finish trips, officer screens toggle
duty and acknowledge alerts, and admin screens retrieve overview and approvals.

The backend creates an OSRM route and stores its GeoJSON on a trip. Driver
location socket events update the trip and invoke the Turf corridor service.
That service projects officers and the ambulance onto the route and compares
distance ahead, distance from the route and ETA. Alerts are stored against a
unique trip/officer pair, delivered via sockets and optionally push, and
acknowledgements are broadcast back to the driver and admin. The simulator
provides the moving driver location events currently missing from the mobile app.

## APK issue addressed

The supplied screenshot is a development-server connection failure, before app
JavaScript starts. Native `MainApplication.kt` enables developer support using
`BuildConfig.DEBUG`; debug variants expect Metro. The existing release build
configuration bundles with Expo's `export:embed` and uses Hermes.

`pnpm build:android:apk` now selects `assembleRelease` explicitly, builds shared
code, checks the mobile API environment, verifies an embedded JavaScript asset,
and copies the result to `dist/raahat-release.apk`. README contains Android Studio
and command-line instructions. Metro no longer overrides every generic `index`
import originating outside the mobile directory, which could misresolve libraries.

Native Android sources are ignored by Git and generated by Expo. The build
workflow is therefore kept in tracked files rather than depending on another
manual native patch. Existing local changes to the entry points and dependencies
were retained.

## Remaining implementation gaps

These are source-review findings, not features completed by the APK fix:

| Area | Current behavior | Next development step |
| --- | --- | --- |
| Driver and officer GPS | One-shot foreground location reads; active trip and duty screens do not stream location | Implement authenticated location subscriptions and Android background tasks/foreground service, with cleanup and offline handling |
| Native maps | `CorridorMap` renders Leaflet only on web; Android renders decorative mock shapes | Implement a real native map and render actual route/officer data |
| Authentication | Token is memory-only; role switching can retain the previous connected socket | Secure persistence, reconnect on identity change, reset role-specific stores |
| Admin navigation | Root login and persona switching route admins to `/home`; alternate login routes correctly | Unify role routing and screen access guards |
| Status and history | Sample officers, completed trips, speed, GPS accuracy and connection labels; admin failures substitute demo data | Bind displays to real state and expose empty/error/disconnected states |
| Push alerts | Client channel `emergency_corridor` differs from server `emergency_siren_channel`; no EAS project ID or Firebase Android config in app.json | Complete native push setup and test delivery on locked physical devices |
| Alert modal | Acknowledgement is shown before the API succeeds; no implemented native siren/full-screen lock-screen flow | Await server acknowledgement, handle failures, implement and device-test notification behavior |
| Corridor freshness | Engine uses 30 minutes and accepts null timestamps despite shared 60-second setting | Apply the shared freshness policy and tests for stale/off-route/behind officers |
| Routing failure | OSRM failure returns a straight line with fixed 5 km / 600 s values | Show routing failure or explicitly labeled demo mode |
| Server authorization | Public registration accepts and auto-verifies ADMIN; socket handlers lack schema validation and verified/duty enforcement | Restrict admin provisioning and enforce authorization/validation on all event paths |
| Trip lifecycle | End/cancel does not dismiss outstanding alerts; concurrent create checks can race | Make lifecycle transitions and alert cleanup consistent and atomic |

Before extending the demo into a field pilot, prioritize real location delivery,
honest connection/error states, server authorization, and physical-device push
verification. A successful release APK build establishes packaging, not these
end-to-end capabilities.
